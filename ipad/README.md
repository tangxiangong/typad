# iPad 开发

在 `macos/TyPad.xcodeproj` 中选择 **TyPad-iPad** scheme；原来的 **TyPad** scheme 继续构建 macOS 应用。iPad Target 最低支持 iPadOS 17，仅包含 iPad 设备族。

```sh
# arm64 iPad 设备构建，不签名、不连接设备
bash ipad/build.sh
# arm64 模拟器构建，不启动模拟器
bash ipad/build.sh --simulator
```

真机运行或归档时，在 Xcode 的 TyPad-iPad Target 中配置自己的 Signing Team。命令行脚本默认禁用签名，仅用于构建验证。

## 功能与平台边界

- 使用系统文档浏览器新建、打开、保存 `.typ` 文档。
- 原生 UIKit 编辑器支持中文输入、系统查找及动态字体；各标签独立记录文本编辑的撤销/重做历史。文档选项菜单提供“撤销 / 重做”，软件键盘隐藏或显示预览时也可使用。
- 宽窗口并排显示源码和 PDF，窄窗口通过分段控件切换。
- 后台本地 Typst 编译、350 ms 防抖、错误诊断及 PDF 导出；编译失败保留上次成功预览，过期预览不能导出。
- 多个窗口共用串行编译队列，避免同时运行多个内存密集编译。原生编译运行中不能强制终止；关闭文档或编辑后的旧结果会被丢弃。
- 通过文档选项中的“允许资源文件夹…”授权文档所在文件夹后，编译器可读取同目录资源。授权在当前文档会话内使用，重新打开时需重新选择；云端资源需要已下载。

iPad 使用现有 `typad-ffi` 的快照编译接口，不启动 `typad-worker`，也没有 macOS 工作进程的崩溃隔离。当前 iPad 编译后端不支持 Typst 包导入；Tinymist 补全、快速帮助及文档大纲侧栏尚未移植。

项目工作区支持新建/打开文件夹、最近项目、文件树、新建文本文件、多标签、固定主文档、未保存多文件快照编译、全部保存、外部修改冲突阻止及恢复快照。项目树和标签使用 Catppuccin 图标（包括 `asset/` 的专用展开/折叠图标）；标签各自保留 UIKit 编辑器、选区、滚动和撤销记录。关闭项目或标签时提供保存、放弃、取消；进入后台时立即落盘恢复快照。

iPadOS 18 及以上在系统文档启动页提供“项目”入口；iPadOS 17 从文档编辑器的“文档选项 → 项目”进入。最近项目使用 Files 书签恢复权限；失效时重新选择文件夹。新建项目先选择上级文件夹，不覆盖已有目录。项目权限在工作区使用期间保持，后台编译另持有资源访问权限。云端文件需先下载。项目读写通过后台 `NSFileCoordinator` 与文件提供方协调：目录逐层扫描，Rust 通过 FFI 回调逐文件读取磁盘资源；保存的磁盘比较和写入在同一次协调中执行，等待期间显示进度并防止重复操作。

恢复快照使用容器内稳定的项目标识和项目相对文件路径；应用更新或 Xcode 重装改变数据容器路径后仍可恢复，并依据可解析的旧项目书签迁移旧格式快照。最近项目按解析后的稳定标识去重，恢复成功使用独立提示。

iPad 随包提供 Noto Sans SC 常规/粗体（约 16 MiB，SIL OFL 1.1；来源与校验见 [字体说明](Resources/Fonts/README.md)）。系统字体若只有不受排版器支持的字形格式，则不参与字体回退，避免 PDF 可提取中文却没有可见字形。

macOS 项目专项实机结果不代表 iPad 触控和界面验收。`ci/check-ipad.sh` 在 arm64 主机上验证共享 FFI 的实际 PDF 输出、中文像素渲染、未保存子文件覆盖/释放以及 Unicode 编辑差异逆操作；设备、模拟器构建和界面验收分别记录。

## 构建组织

- `TyPad-iPad` → `TyPadCore-iPad` → `RustBindings-iPad`。
- 与 macOS 共享 `TypstDocument.swift`、`ProjectWorkspace.swift`、`FileIcon.swift`、图标、本地化资源和 Rust 核心。
- 生成的 Swift 模块名保持 `TyPadCore`，绑定输出按配置和平台分目录，设备与模拟器的静态库不混用。
- macOS arm64 构建后运行 `bash ci/check-ipad.sh`，在本机验证 iPad 编译模型的防抖、真实 PDF 输出、错误恢复和取消行为，不启动 GUI。
- `bash ci/check-macos.sh` 同时检查两个平台的 plist、scheme、脚本及 Swift 语法；平台类型检查和链接由对应 Xcode 构建完成。
